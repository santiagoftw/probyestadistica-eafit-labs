Bloque 0 · Cómo importar los datos

Importar bien el archivo es el primer obstáculo real de cualquier laboratorio. Estas son las cuatro opciones, de la más recomendada a la más manual:

  • Opción A · Ruta relativa (proyecto)
  • Opción B · Posit Cloud
  • Opción C · Fijar el directorio con setwd()
  • Opción D · Selección interactiva

Si trabajas dentro de un proyecto de RStudio (o clonaste el repositorio del curso), y el CSV está en una subcarpeta data/, basta con la ruta relativa:

datos <- read.csv("data/BaseLaboratorio1.csv")

Es la opción más portable: funciona igual en cualquier computador que tenga la misma estructura de carpetas. Requisito: el directorio de trabajo debe ser la raíz del proyecto (verifícalo con getwd()).

En Posit Cloud, los archivos que subes quedan en /cloud/project/. Sube el CSV con el botón “Upload” del panel Files, y luego:

datos <- read.csv("/cloud/project/BaseLaboratorio1.csv")

Esta es exactamente la ruta que usa la solución oficial del laboratorio del curso.

Puedes indicarle a R en qué carpeta buscar los archivos con setwd(), y después leer con el nombre del archivo solamente:

setwd("C:/Users/tu_usuario/Documents/estadistica")  # Windows
# setwd("/Users/tu_usuario/Documents/estadistica")  # Mac
datos <- read.csv("BaseLaboratorio1.csv")

Advertencia: la ruta depende de cómo esté organizado tu computador — un script con setwd() de rutas absolutas no funcionará en el computador de tu compañero. Úsalo para trabajo personal, no para scripts que vayas a compartir.

Si no quieres escribir ninguna ruta, file.choose() abre una ventana para navegar hasta el archivo:

datos <- read.csv(file.choose())

Cómodo para una sesión rápida, pero no reproducible: quien corra tu script tendrá que buscar el archivo a mano cada vez. Evítalo en trabajos entregables.

ImportantLos argumentos de read.csv() que debes conocer

read.csv() asume separador de columnas , y punto decimal .. Si tu archivo viene de un Excel en español (separador ; y decimal ,), esos supuestos fallan y debes declararlos explícitamente:

datos <- read.table("archivo.csv", header = TRUE, sep = ";", dec = ",")
  • header = TRUE: la primera fila trae los nombres de las columnas.
  • sep: el carácter que separa columnas ("," o ";").
  • dec: el carácter decimal ("." o ",").

De hecho, read.csv() es solo un atajo de read.table() con sep = "," y header = TRUE ya predefinidos. Si al importar ves una sola columna gigante con todo pegado, casi siempre el problema es el sep.

Verifica siempre la importación antes de analizar — estas dos líneas te ahorran horas de errores silenciosos:

Ítem 3 — Clasificar las variables

Enunciado: clasifique las variables entre categóricas y cuantitativas. Para las categóricas, diga si son nominales u ordinales; para las cuantitativas, si son discretas o continuas.

  • Tu turno
  • Solución oficial

Antes de ver la solución oficial, clasifica cada una de las 7 columnas usando lo aprendido en el Tema 1.

El dataset tiene 7 variables. Dos son categóricas: Year y Country; el resto son cuantitativas continuas, asociadas a la producción anual de energía: SolarEnergy, WindEnergy, HydroEnergy, OtherRenewableEnergy, TotalRenewableEnergy. Hay 240 registros: 24 por país (10 países × 24 años, del 2000 al 2023).

Nota de rigor: Year se guarda como int en R, pero estadísticamente es más apropiado tratarla como variable ordinal (o incluso como índice temporal) que como cuantitativa de razón — no tiene sentido, por ejemplo, promediar años. Country es claramente nominal: no hay orden natural entre países.

🗂️ Cierre del Laboratorio 1

  • La clasificación correcta de variables es la base de cualquier análisis descriptivo correcto — un error aquí invalida todo lo que sigue.
  • Comparar media y mediana es la forma más rápida de detectar asimetría antes de graficar nada.
  • El coeficiente de variación permite comparar la dispersión relativa entre las 4 fuentes de energía, aunque tengan escalas de producción distintas.
  • Las medidas basadas en cuantiles (RIC, RID, RIP) son robustas ante atípicos — útiles cuando, como aquí, los datos vienen de países con economías y capacidades energéticas muy distintas entre sí.

Ítem 13 — Probabilidad de un número par (teórica vs. simulada)

Enunciado: calcule la probabilidad de obtener un número par al lanzar un dado de seis caras. Luego simule el lanzamiento del dado 1000 veces y verifique la frecuencia de números pares.

¿Qué tan cerca esperas que quede la frecuencia simulada de la probabilidad teórica con solo 1000 lanzamientos?

Code 
prob_par <- 3 / 6  # hay 3 números pares en un dado de 6 caras

set.seed(123)
lanzamientos <- sample(1:6, size = 1000, replace = TRUE)
frecuencia_par <- mean(lanzamientos %% 2 == 0)

prob_par

Bloque 17 · Funciones generadoras de momentos (FGM)

🧮 Una “huella digital” para cada distribución

La función generadora de momentos \(m_X(t)=E(e^{tX})\) empaqueta todos los momentos de una variable aleatoria (\(E[X]\), \(E[X^2]\), …) en una sola expresión, y tiene una propiedad clave: si dos variables tienen la misma FGM, tienen la misma distribución. Es la herramienta que permite, por ejemplo, demostrar que la suma de Poisson independientes es Poisson (Ítem 45) sin tener que enumerar combinaciones.

Ítem 46 — Reconstruir una distribución a partir de su FGM

Enunciado: un dado de 4 caras (valores 1 a 4, equiprobables) tiene función de probabilidad conocida. (a) Encuentre su FGM. (b) A partir de \(m_X'(0)\) y \(m_X''(0)\), calcule \(E[X]\), \(E[X^2]\) y \(\text{Var}(X)\).

Code 
# Verificación simbólica no está disponible en R base sin paquetes adicionales,
# así que verificamos las derivadas evaluadas en t=0 por simulación y por fórmula directa
valores <- 1:4
prob <- rep(1/4, 4)

# E[X] y E[X^2] directos (equivalen a m'(0) y m''(0))
E_X  <- sum(valores * prob)
E_X2 <- sum(valores^2 * prob)
var_X <- E_X2 - E_X^2

c(E_X = E_X, E_X2 = E_X2, Var_X = var_X)
  E_X  E_X2 Var_X 
 2.50  7.50  1.25

\(E[X]=2.5\), \(E[X^2]=7.5\), \(\text{Var}(X)=1.25\) — los mismos valores que se obtienen derivando \(m_X(t)=\frac{1}{4}(e^t+e^{2t}+e^{3t}+e^{4t})\) dos veces y evaluando en \(t=0\). La FGM no es más que una forma compacta de “empacar” estos cálculos: derivar y evaluar en 0 siempre reproduce \(E[X^k]\).

Enunciado: para cada pregunta, justifique la respuesta correcta.

Dos procesos A y B tienen la misma media (100Ω); A tiene desviación estándar 2Ω y B tiene 8Ω. Para minimizar componentes fuera de especificación, ¿cuál preferir?

Respuesta: preferir A. Con la misma media, una menor desviación estándar significa que las mediciones individuales se alejan menos del valor central — es decir, mayor precisión y consistencia. Un valor extremo ocasional en B (con 4 veces más dispersión) tiene mucha más probabilidad de caer fuera de especificación, aunque el promedio de B sea idéntico al de A.

Un ingeniero clasifica “número de revoluciones” y “tiempo para alcanzar cierta temperatura”. ¿Cuál es la clasificación correcta?

Respuesta: revoluciones es discreta; tiempo es continua. Las revoluciones se cuentan (números enteros, con saltos entre valores posibles); el tiempo es el resultado de una medición y puede tomar, en principio, cualquier valor dentro de un intervalo, limitado solo por la precisión del instrumento — la misma distinción que se trabajó en el Tema 1 del Módulo 1.

Un analista usa la “media recortada al 10%” para evitar que errores de registro muy altos o bajos distorsionen el resultado. ¿Cuál es el objetivo?

Respuesta: generar un estimador robusto, no influenciado por los extremos. Recortar el 10% superior e inferior antes de promediar es un punto intermedio entre la media (sensible a outliers) y la mediana (totalmente robusta) — mismo espíritu que el Ítem 12 (rango intercuartil e interpercentil) del Laboratorio 1.

En un boxplot comparativo, la Marca X tiene la caja más ancha que la Marca Y, con las mismas medianas. ¿Qué se concluye?

Respuesta: la Marca Y es más confiable en consistencia (menor IQR). Una caja más ancha significa un rango intercuartílico mayor — el 50% central de los datos está más disperso. Con medianas iguales, la diferencia no está en el “centro típico” sino en qué tan predecible es cada marca.

¿Cuál es la ventaja del rango intercuartílico (IQR) sobre el rango total (R) para describir precios de vivienda?

Respuesta: el IQR ignora los precios extremos (mansiones o propiedades en ruina) que distorsionarían la variabilidad típica del mercado. El rango total usa solo el máximo y el mínimo, así que un único valor atípico —en cualquiera de los dos extremos— puede inflarlo por completo; el IQR, al basarse en el 50% central, es una medida de dispersión mucho más robusta para este tipo de datos.

Razón, proporción y tasa se calculan todas dividiendo un número entre otro — pero no son intercambiables. Distinguirlas es clave en cualquier contexto de salud pública o epidemiología, donde un mismo cociente mal etiquetado puede llevar a una interpretación equivocada.

mu <- n * p; sigma <- sqrt(n * p * (1 - p))
c(np = n*p, n1p = n*(1-p), mu = mu, sigma = sigma)   # verificación de la regla práctica

Code 
exacto <- pbinom(180, n, p) - pbinom(159, n, p)

\(np=165\ge5\) y \(n(1-p)=135\ge5\): la aproximación es válida. El valor exacto es 0.7031 y el aproximado (con corrección de continuidad) es 0.7023 — una diferencia de apenas 0.0008, prácticamente despreciable con \(n=300\).

Bloque 25 · Función generadora de momentos

Ítem 63 — Momentos de una Bernoulli, paso a paso

Enunciado: a partir de la FGM de una Bernoulli(\(p\)), \(M(t)=1-p+pe^t\), calcule \(E[X]\) y \(\text{Var}(X)\) derivando y evaluando en \(t=0\) — primero a mano, luego verificando en R con derivación numérica.

Code 
p <- 0.35   # un valor concreto para verificar numéricamente

M <- function(t) 1 - p + p * exp(t)

h <- 1e-6
E_X   <- (M(h) - M(-h)) / (2*h)
E_X2  <- (M(h) - 2*M(0) + M(-h)) / h^2
Var_X <- E_X2 - E_X^2

c(E_X = E_X, Var_X = Var_X, p_teorico = p, "p(1-p)_teorico" = p*(1-p))
           E_X          Var_X      p_teorico p(1-p)_teorico 
     0.3500000      0.2275533      0.3500000      0.2275000
ImportantEl álgebra detrás del chunk

A mano: \(M'(t)=pe^t\), así que \(M'(0)=p=E[X]\). \(M''(t)=pe^t\) también, así que \(M''(0)=p=E[X^2]\). Entonces \(\text{Var}(X)=E[X^2]-E[X]^2=p-p^2=p(1-p)\) — coincide exactamente con lo que ya sabías de la tabla del Tema P6d, y con el resultado numérico de arriba.

Ítem 64 — Identificar una suma usando FGM

Enunciado: \(X\sim\text{Poisson}(3)\) y \(Y\sim\text{Poisson}(5)\), independientes. (a) Use el producto de sus FGM para identificar la distribución de \(X+Y\). (b) Calcule \(P(X+Y=10)\).

Code 
lambda_X <- 3; lambda_Y <- 5

# (a) Verificación algebraica: el producto de las FGM tiene forma de Poisson(lambda_X + lambda_Y)
M_pois <- function(t, lambda) exp(lambda * (exp(t) - 1))
t_prueba <- seq(-1, 1, 0.2)
max(abs(M_pois(t_prueba, lambda_X) * M_pois(t_prueba, lambda_Y) - M_pois(t_prueba, lambda_X + lambda_Y)))
[1] 1.164153e-10
Code 
# (b) Con X+Y ~ Poisson(8):
p_suma_10 <- dpois(10, lambda_X + lambda_Y)
p_suma_10
[1] 0.09926153

La diferencia máxima entre el producto de FGM y la FGM de Poisson(8) es esencialmente cero: confirma que \(X+Y\sim\text{Poisson}(8)\). Con eso, \(P(X+Y=10)=0.0993\) — un cálculo directo con dpois(), sin necesidad de convolucionar las dos distribuciones originales.

🗂️ Cierre del Taller 2

  • Binomial: identifica \(n\) y \(p\), y decide entre dbinom() (exactamente), pbinom() (acumulada) y su complemento (al menos), sin confundir el valor esperado con la meta de la pregunta.
  • Poisson: el paso que más se olvida es ajustar \(\lambda\) al intervalo real de la pregunta — hazlo siempre antes de llamar a dpois()/ppois().
  • Aproximación normal: verifica \(np\ge5\) y \(n(1-p)\ge5\) antes de usarla, y nunca olvides la corrección de continuidad (±0.5) — la diferencia entre usarla y no usarla puede ser el margen entre acertar y fallar un punto del examen.
  • FGM: derivar y evaluar en \(t=0\) da los momentos; multiplicar FGM de variables independientes da la FGM de su suma — dos atajos que reemplazan sumas directas y convoluciones tediosas.

::: {.callout-important}
## Los argumentos de `read.csv()` que debes conocer
`read.csv()` asume separador de columnas `,` y punto decimal `.`. Si tu archivo viene de un Excel en español (separador `;` y decimal `,`), esos supuestos fallan y debes declararlos explícitamente:

```r
datos <- read.table("archivo.csv", header = TRUE, sep = ";", dec = ",")
```

- `header = TRUE`: la primera fila trae los nombres de las columnas.
- `sep`: el carácter que separa columnas (`","` o `";"`).
- `dec`: el carácter decimal (`"."` o `","`).

De hecho, `read.csv()` es solo un atajo de `read.table()` con `sep = ","` y `header = TRUE` ya predefinidos. Si al importar ves una sola columna gigante con todo pegado, casi siempre el problema es el `sep`.
:::

**Verifica siempre la importación antes de analizar** — estas dos líneas te ahorran horas de errores silenciosos:

```{r}
datos <- read.csv("data/BaseLaboratorio1.csv")
dim(datos)    # ¿240 filas y 7 columnas? entonces cargó bien
head(datos, 3)
```

## Corrección de rigor
La solución oficial del laboratorio calcula "al menos uno" como `1-(p1+p2-p12)` y obtiene 0.3 — pero esa expresión es en realidad $P(\text{ninguno de los dos})=1-P(A\cup B)$, no $P(\text{al menos uno})$. Este es el mismo error que se documentó en el banco de ejercicios del Módulo 2 (ejercicio 1), donde se dejó explícitamente como ejercicio de detección de errores.

## Bloque 8 · Distribución de probabilidad conjunta

### Ítem 29 — Monedas: conjunta, marginal y condicional (con corrección)

**Enunciado:** se lanzan 3 monedas balanceadas. $Y_1$ = número de caras. $Y_2$ = ganancia de una apuesta: \$1 si la primera cara sale en el tiro 1, \$2 si sale en el tiro 2, \$3 si sale en el tiro 3, y $-\$1$ si no sale ninguna cara. Encuentre la función de probabilidad conjunta, la marginal de $Y_2$, y $P(Y_1=3\,|\,Y_2=1)$.

::: {.ficha-prediccion}
$Y_2$ depende del *momento* de la primera cara, y $Y_1$ del *número total* de caras — dos aspectos distintos del mismo lanzamiento. ¿Esperas que sean independientes?
:::

```{r}
monedas <- expand.grid(t1 = c("C", "S"), t2 = c("C", "S"), t3 = c("C", "S"))
monedas$Y1 <- rowSums(monedas[, 1:3] == "C")
monedas$Y2 <- apply(monedas[, 1:3], 1, function(fila) {
  pos <- which(fila == "C")
  if (length(pos) == 0) return(-1)
  min(pos)
})

prob_matrix <- table(monedas$Y1, monedas$Y2) / nrow(monedas)
prob_matrix

marginal_Y2 <- colSums(prob_matrix)
marginal_Y2

p_Y1_3_dado_Y2_1 <- prob_matrix["3", "1"] / marginal_Y2["1"]
p_Y1_3_dado_Y2_1
```

::: {.callout-important}
## Corrección de rigor
La solución oficial de este laboratorio construye la tabla conjunta con una función que solo cubre la diagonal ($Y_1=y \Rightarrow Y_2=y$), lo que deja fuera combinaciones reales: por ejemplo, `CCS` y `CSC` dan ambas $Y_1=2$ pero con la primera cara en el tiro 1 ($Y_2=1$), no en el tiro 2. Esa función asigna probabilidad 0 a `(Y1=2, Y2=1)` cuando en realidad vale $2/8$, y de paso hace que la marginal de $Y_2$ salga uniforme (0.125 en cada valor) cuando la real es $P(Y_2{=}1){=}0.5$, $P(Y_2{=}2){=}0.25$, $P(Y_2{=}3){=}0.125$, $P(Y_2{=}{-1}){=}0.125$. La forma robusta de evitar este tipo de error — y la que se usa arriba — es **enumerar los 8 resultados del espacio muestral y contar**, en vez de escribir de memoria una fórmula cerrada para la probabilidad conjunta. Esta misma corrección ya se aplicó al Tema P8 del Módulo 2.
:::

::: {.ficha-resultado}
Con la tabla corregida, $P(Y_1{=}3\,|\,Y_2{=}1)=0.25$: saber que ganaste \$1 (la cara salió en el primer tiro) sí cambia la probabilidad de haber sacado 3 caras respecto a la marginal $P(Y_1{=}3)=0.125$ — confirma que **no son independientes**.
:::

### Ítem 30 — Ejecutivos: conjunta hipergeométrica y condicional (con corrección)

**Enunciado:** de 9 ejecutivos (4 casados, 3 solteros, 2 divorciados) se seleccionan 3 al azar. $Y_1$ = número de casados, $Y_2$ = número de solteros seleccionados. (1) Encuentre la conjunta. (2) La marginal de $Y_1$. (3) $P(Y_1{=}1\,|\,Y_2{=}2)$. (4) Si $Y_3=3-Y_1-Y_2$ es el número de divorciados, calcule $P(Y_3{=}1\,|\,Y_2{=}1)$.

```{r}
total <- 9; casados <- 4; solteros <- 3; divorciados <- 2; sel <- 3

prob_conjunta <- function(y1, y2) {
  y3 <- sel - y1 - y2
  if (y3 < 0 || y3 > divorciados) return(0)
  (choose(casados, y1) * choose(solteros, y2) * choose(divorciados, y3)) / choose(total, sel)
}

Y1 <- 0:3; Y2 <- 0:3
prob_matrix <- outer(Y1, Y2, Vectorize(prob_conjunta))
rownames(prob_matrix) <- paste0("Y1=", Y1); colnames(prob_matrix) <- paste0("Y2=", Y2)
round(prob_matrix, 4)

marginal_Y1 <- rowSums(prob_matrix)
marginal_Y1

# (3) P(Y1=1 | Y2=2)
p_Y1_1_dado_Y2_2 <- prob_conjunta(1, 2) / sum(prob_matrix[, "Y2=2"])
p_Y1_1_dado_Y2_2

# (4) P(Y3=1 | Y2=1): si Y2=1, Y3=1 exige Y1 = 3-1-1 = 1 (no Y1=2)
p_Y2_1 <- sum(prob_matrix[, "Y2=1"])
p_Y3_1_dado_Y2_1 <- prob_conjunta(1, 1) / p_Y2_1
p_Y3_1_dado_Y2_1
```

::: {.callout-important}
## Corrección de rigor
La solución oficial calcula el punto (4) así: `prob_Y1_2_Y2_1 <- prob_joint(2, 1)` dividido entre una variable `prob_Y2_1` que **no se redefine** en ese punto del documento — sigue guardando el valor 0.125 de un ejercicio anterior (el de las monedas), no la marginal de este problema. El resultado que imprime, 1.714286, ya es una señal de alerta por sí sola: **ninguna probabilidad puede ser mayor que 1**. Además, usa $Y_1{=}2$ cuando la condición $Y_3{=}1, Y_2{=}1$ en realidad exige $Y_1{=}3-1-1{=}1$. Al corregir ambos puntos (variable correcta y valor de $Y_1$ correcto), $P(Y_3{=}1\,|\,Y_2{=}1)\approx0.533$. La lección: reutilizar nombres de variable entre secciones de un mismo script es una fuente común de errores silenciosos — y un resultado fuera del rango válido (aquí, una "probabilidad" mayor a 1) siempre debe hacer sospechar del código antes que del modelo.
:::

```{r}
mean_E <- 200; sd_E <- 20
cor_RE <- 0.6

cov_matrix <- matrix(c(sd_R^2, cor_RE * sd_R * sd_E,
                        cor_RE * sd_R * sd_E, sd_E^2), 2, 2)

set.seed(123)
propiedades <- mvrnorm(10000, mu = c(mean_R, mean_E), Sigma = cov_matrix)
R <- propiedades[, 1]; E <- propiedades[, 2]
vida_util <- R^2 / E

list(
  media_vida_util = mean(vida_util),
  sd_vida_util = sd(vida_util),
  correlacion_L_R = cor(vida_util, R)
)
```

::: {.callout-tip}
## 💡 Truco de interpretación
$L$ es una función **no lineal** de $R$ y $E$, así que no hay una fórmula cerrada simple para su media o varianza (a diferencia de una combinación lineal). Por eso se simula: generar miles de escenarios y calcular la media/varianza empíricas es, en la práctica, la manera más directa de propagar la incertidumbre a través de una función complicada. [Ver más trucos →](recursos.qmd)
:::

## Bloque 14 · Estimación por intervalos

### Ítem 40 — Intervalo de confianza del 95% para una media

**Enunciado:** una muestra de 120 estudiantes reporta un tiempo promedio de trabajo independiente de 15 horas/semana, con desviación estándar 3 horas. Calcule el intervalo de confianza del 95% para la media poblacional.

```{r}
media_muestral <- 15; sd_muestral <- 3; n <- 120
confianza <- 0.95

SE <- sd_muestral / sqrt(n)
valor_critico <- qnorm(1 - (1 - confianza) / 2)
margen_error <- valor_critico * SE

c(inferior = media_muestral - margen_error, superior = media_muestral + margen_error)
```

::: {.callout-tip}
## 💡 Truco de interpretación
La estructura **estimación ± (valor crítico × error estándar)** es la misma para casi cualquier intervalo de confianza clásico — solo cambian el valor crítico (normal, t, etc.) y la fórmula del error estándar según qué parámetro se está estimando. [Ver más trucos →](recursos.qmd)
:::

### Ítem 41 — Intervalo de confianza del 95% para una proporción (Wilson)

**Enunciado:** de una muestra de 300 estudiantes, 60% tienen empleo de medio tiempo. Calcule el intervalo de confianza del 95% para la proporción poblacional, usando el método de Wilson.

```{r}
proporcion <- 0.60
n <- 300

# prop.test() viene en el paquete `stats` (base R, no requiere instalar nada)
# y calcula el intervalo de Wilson cuando correct = FALSE
prop.test(n * proporcion, n, correct = FALSE)$conf.int
```

::: {.callout-important}
## Nota de compatibilidad
La solución oficial del laboratorio usa `Hmisc::binconf(..., method = "wilson")`, pero `Hmisc` **no viene instalado por defecto** en R/RStudio — hay que instalarlo aparte (`install.packages("Hmisc")`), y en algunos entornos (como Posit Cloud gratuito) la instalación puede fallar o tardar mucho por sus dependencias. `prop.test()` calcula exactamente el mismo intervalo de Wilson (verificado: da el mismo resultado, 0.544 a 0.654) sin depender de ningún paquete externo — viene incluido en el paquete `stats`, que R carga automáticamente al iniciar. Si en algún momento necesitas `Hmisc` específicamente, instálalo con `install.packages("Hmisc")` antes de tu primer `library(Hmisc)`.
:::

::: {.callout-note}
## ¿Por qué Wilson y no la fórmula clásica?
El método clásico ($\hat{p}\pm z\sqrt{\hat{p}(1-\hat{p})/n}$) puede dar intervalos mal calibrados cuando $\hat{p}$ está cerca de 0 o 1, o con $n$ moderado. Wilson corrige ese problema y es el método que recomiendan la mayoría de paquetes estadísticos modernos como opción por defecto.
:::

## Bloque 15 · Pruebas de hipótesis

### Ítem 42 — Prueba t: ¿son distintos dos algoritmos?

**Enunciado:** se comparan dos algoritmos de interacción midiendo su tiempo de respuesta ($A\sim N(55,15^2)$, $B\sim N(50,5^2)$, 1000 usuarios cada uno). Plantee el contraste de hipótesis y concluya.

::: {.panel-tabset}

## Hipótesis
$H_0: \mu_A = \mu_B$ vs. $H_1: \mu_A \ne \mu_B$ (contraste bilateral). El estadístico de prueba sigue una distribución t de Student (Welch, porque no se asume igualdad de varianzas).

## Código y conclusión

```{r}
set.seed(42)
n_A <- 1000; n_B <- 1000
tiempos_A <- rnorm(n_A, mean = 55, sd = 15)
tiempos_B <- rnorm(n_B, mean = 50, sd = 5)

t.test(tiempos_A, tiempos_B)
```

Con un p-valor prácticamente cero (< 2.2e-16), se **rechaza $H_0$**: hay evidencia estadística muy fuerte de que los tiempos de respuesta promedio de los dos algoritmos son distintos. El intervalo de confianza de la diferencia (aprox. 3.7 a 5.6) tampoco incluye el cero, lo cual es consistente con el rechazo.

:::

### Ítem 43 — Comparando varianzas y medias: instrumento nuevo vs. estándar

**Enunciado:** se comparan mediciones de un instrumento nuevo ($\mu=0.07$, $\sigma=0.05$) contra uno estándar ($\mu=0.08$, $\sigma=0.010$), 100 mediciones cada uno. Evalúe si difieren en varianza y en media.

```{r}
set.seed(42)
n <- 100
nuevo <- rnorm(n, mean = 0.07, sd = 0.05)
estandar <- rnorm(n, mean = 0.08, sd = 0.010)

var.test(nuevo, estandar)
t.test(nuevo, estandar)
```

::: {.ficha-resultado}
La prueba F de varianzas da un p-valor prácticamente cero: el instrumento nuevo es **significativamente más disperso** (menos preciso) que el estándar — su desviación estándar real (0.05) es 5 veces mayor. Sin embargo, la prueba t sobre las medias da p ≈ 0.16: **no hay evidencia suficiente para decir que difieran en promedio**. Es un buen ejemplo de que "distinto en precisión" y "distinto en promedio" son preguntas independientes — un instrumento puede ser igual de "centrado" pero mucho más ruidoso.
:::

::: {.callout-tip}
## 💡 Truco de interpretación
No confundas "no rechazar $H_0$" con "demostrar que $H_0$ es cierta". Un p-valor de 0.16 en la prueba t solo dice que los datos no dan evidencia suficiente para descartar medias iguales — no prueba que las medias sean exactamente iguales. [Ver más trucos →](recursos.qmd)
:::

```{r}
# (a) Internet café
dbinom(10, size = 16, prob = 0.75)

dbinom(6, size = 50, prob = 0.12)

# (c) adivinar en un examen: P(X>=10) para distintos k
n_preguntas <- 15

```

### Ítem 45 — Poisson: eventos raros en un intervalo

**Enunciado:** tres escenarios de conteo de eventos raros — (a) el número de goles de dos equipos en un partido de hockey son Poisson independientes con medias 2.5 y 1.5; ¿cuál es la probabilidad de que el total de goles sea a lo sumo 3?; (b) un corrector de estilo encuentra errores a una tasa de 0.09 por página; en un documento de 50 páginas, ¿cuál es la probabilidad de encontrar 3 o más errores?; (c) un catálogo tiene una tasa de defectos del 5%; en una muestra de 100 artículos (aproximando la binomial con Poisson), ¿cuál es la probabilidad de encontrar a lo sumo 10 defectuosos?

## Bloque 17 · Funciones generadoras de momentos (FGM)

::: {.hero-motivacion}
## 🧮 Una "huella digital" para cada distribución

La función generadora de momentos $m_X(t)=E(e^{tX})$ empaqueta todos los momentos de una variable aleatoria ($E[X]$, $E[X^2]$, ...) en una sola expresión, y tiene una propiedad clave: si dos variables tienen la misma FGM, tienen la misma distribución. Es la herramienta que permite, por ejemplo, demostrar que la suma de Poisson independientes es Poisson (Ítem 45) sin tener que enumerar combinaciones.
:::

### Ítem 46 — Reconstruir una distribución a partir de su FGM

**Enunciado:** un dado de 4 caras (valores 1 a 4, equiprobables) tiene función de probabilidad conocida. (a) Encuentre su FGM. (b) A partir de $m_X'(0)$ y $m_X''(0)$, calcule $E[X]$, $E[X^2]$ y $\text{Var}(X)$.

```{r}
# Verificación simbólica no está disponible en R base sin paquetes adicionales,
# así que verificamos las derivadas evaluadas en t=0 por simulación y por fórmula directa
valores <- 1:4
prob <- rep(1/4, 4)

# E[X] y E[X^2] directos (equivalen a m'(0) y m''(0))
E_X  <- sum(valores * prob)
E_X2 <- sum(valores^2 * prob)
var_X <- E_X2 - E_X^2

c(E_X = E_X, E_X2 = E_X2, Var_X = var_X)
```

::: {.ficha-resultado}
$E[X]=2.5$, $E[X^2]=7.5$, $\text{Var}(X)=1.25$ — los mismos valores que se obtienen derivando $m_X(t)=\frac{1}{4}(e^t+e^{2t}+e^{3t}+e^{4t})$ dos veces y evaluando en $t=0$. La FGM no es más que una forma compacta de "empacar" estos cálculos: derivar y evaluar en 0 siempre reproduce $E[X^k]$.
:::

### Ítem 47 — FGM de una suma de variables independientes

**Enunciado:** si $X$ y $Y$ son independientes con $m_X(t)=\frac{1}{1-5t}$ y $m_Y(t)=\frac{1}{(1-5t)^2}$ (ambas exponenciales tipo Gamma), la FGM de la suma es el producto $m_{X+Y}(t)=m_X(t)\cdot m_Y(t)$. Verifique que $E[(X+Y)^2]=300$.

```{r}
# m_{X+Y}(t) = 1 / (1-5t)^3  -> es la FGM de una Gamma(forma = k = 3, escala = theta = 5)
# Para una Gamma(k, escala=theta): E[W] = k*theta, Var(W) = k*theta^2
k <- 3; theta <- 5
E_W  <- k * theta
Var_W <- k * theta^2
E_W2 <- Var_W + E_W^2
c(E_W = E_W, Var_W = Var_W, E_W2 = E_W2)
```

::: {.callout-tip}
## 💡 Por qué importa
Sumar FGMs (multiplicándolas, porque $m_{X+Y}=m_X\cdot m_Y$ cuando hay independencia) evita tener que encontrar la distribución de $X+Y$ por convolución. Es exactamente el mismo principio detrás del Ítem 45(a): $\text{Pois}(\lambda_1)+\text{Pois}(\lambda_2)=\text{Pois}(\lambda_1+\lambda_2)$ porque sus FGMs, al multiplicarse, dan la FGM de una Poisson con parámetro $\lambda_1+\lambda_2$. **Advertencia:** esta propiedad de "cerradura bajo sumas" no es automática para cualquier familia — por ejemplo, la suma de dos exponenciales independientes **no** es exponencial (su FGM producto no tiene la forma $\frac{\lambda}{\lambda-t}$ de una exponencial), aunque sí es Gamma. [Ver más trucos →](recursos.qmd)
:::

## Bloque 18 · Distribuciones conjuntas: casos adicionales

### Ítem 48 — Deducibles de seguro: conjunta, covarianza e independencia

**Enunciado:** una aseguradora modela conjuntamente el deducible de una póliza de auto ($X\in\{1,2,3\}$, en unidades de \$100) y de vivienda ($Y\in\{1,2\}$) con la matriz de probabilidad conjunta:

$$P(X=x,Y=y) = \begin{pmatrix} 0.20 & 0.10 \\ 0.15 & 0.25 \\ 0.10 & 0.20 \end{pmatrix}$$

Encuentre las marginales, $E[X]$, $E[Y]$, $\text{Cov}(X,Y)$, y determine si son independientes.

```{r}
P <- matrix(c(0.20, 0.10,
              0.15, 0.25,
              0.10, 0.20), nrow = 3, byrow = TRUE,
            dimnames = list(X = 1:3, Y = 1:2))
P

marginal_X <- rowSums(P); marginal_X
marginal_Y <- colSums(P); marginal_Y

E_X <- sum(as.numeric(rownames(P)) * marginal_X)
E_Y <- sum(as.numeric(colnames(P)) * marginal_Y)

E_XY <- sum(outer(as.numeric(rownames(P)), as.numeric(colnames(P))) * P)
Cov_XY <- E_XY - E_X * E_Y
c(E_X = E_X, E_Y = E_Y, E_XY = E_XY, Cov_XY = Cov_XY)

# Independencia: comparar la conjunta contra el producto de marginales
producto_marginales <- outer(marginal_X, marginal_Y)
all.equal(as.matrix(P), producto_marginales, check.attributes = FALSE)
```

::: {.ficha-resultado}
$E[X]=2$, $E[Y]=1.55$, $\text{Cov}(X,Y)=0.10$: covarianza positiva pero pequeña. Al comparar la celda $(X{=}1,Y{=}1)$: $P(X{=}1,Y{=}1)=0.20$ mientras que $P_X(1)\cdot P_Y(1)=0.30\times0.45=0.135$ — no coinciden, así que **no son independientes**, consistente con una covarianza distinta de cero.

**Enunciado:** se lanzan 4 monedas balanceadas (en vez de 3, como en el Ítem 29). $Y_1$ = número de caras. $Y_2$ = ganancia de una apuesta: \$2 si la primera cara sale en el tiro 1, \$3/\$4/\$5 si sale en el tiro 2/3/4, y $-\$2$ si no sale ninguna cara. Encuentre la conjunta, la marginal de $Y_2$, $P(Y_1{=}4\mid Y_2{=}2)$, y determine si $Y_1,Y_2$ son independientes.

## Pregunta 1 — Precisión de dos procesos

Dos procesos A y B tienen la misma media (100Ω); A tiene desviación estándar 2Ω y B tiene 8Ω. Para minimizar componentes fuera de especificación, ¿cuál preferir?

**Respuesta: preferir A.** Con la misma media, una menor desviación estándar significa que las mediciones individuales se alejan menos del valor central — es decir, mayor precisión y consistencia. Un valor extremo ocasional en B (con 4 veces más dispersión) tiene mucha más probabilidad de caer fuera de especificación, aunque el promedio de B sea idéntico al de A.

## Pregunta 2 — Clasificación de variables

Un ingeniero clasifica "número de revoluciones" y "tiempo para alcanzar cierta temperatura". ¿Cuál es la clasificación correcta?

**Respuesta: revoluciones es discreta; tiempo es continua.** Las revoluciones se cuentan (números enteros, con saltos entre valores posibles); el tiempo es el resultado de una medición y puede tomar, en principio, cualquier valor dentro de un intervalo, limitado solo por la precisión del instrumento — la misma distinción que se trabajó en el Tema 1 del Módulo 1.

## Pregunta 3 — Media recortada

Un analista usa la "media recortada al 10%" para evitar que errores de registro muy altos o bajos distorsionen el resultado. ¿Cuál es el objetivo?

**Respuesta: generar un estimador robusto, no influenciado por los extremos.** Recortar el 10% superior e inferior antes de promediar es un punto intermedio entre la media (sensible a outliers) y la mediana (totalmente robusta) — mismo espíritu que el Ítem 12 (rango intercuartil e interpercentil) del Laboratorio 1.

En un boxplot comparativo, la Marca X tiene la caja más ancha que la Marca Y, con las mismas medianas. ¿Qué se concluye?

**Respuesta: la Marca Y es más confiable en consistencia (menor IQR).** Una caja más ancha significa un rango intercuartílico mayor — el 50% central de los datos está más disperso. Con medianas iguales, la diferencia no está en el "centro típico" sino en qué tan predecible es cada marca.

## Pregunta 5 — IQR vs. rango total

¿Cuál es la ventaja del rango intercuartílico (IQR) sobre el rango total (R) para describir precios de vivienda?

**Respuesta: el IQR ignora los precios extremos** (mansiones o propiedades en ruina) que distorsionarían la variabilidad típica del mercado. ## Bloque 20 · Indicadores epidemiológicos: razones, proporciones y tasas

::: {.hero-motivacion}
## 🏥 Cuando "dividir dos números" no siempre significa lo mismo

Razón, proporción y tasa se calculan todas dividiendo un número entre otro — pero no son intercambiables. Distinguirlas es clave en cualquier contexto de salud pública o epidemiología, donde un mismo cociente mal etiquetado puede llevar a una interpretación equivocada.
:::

### Ítem 53 — Razón y proporción

**Enunciado:** (a) una clínica con 500 camas de hospitalización tiene 83 médicos generales de piso — calcule e interprete la razón cama/médico. (b) en una población de 32,000 habitantes se diagnostican 1,789 pacientes con Infarto Agudo del Miocardio (IAM) — calcule la proporción en porcentaje y por cada 1,000 habitantes.

```{r}
# (a) Razón: numerador y denominador son conjuntos DISTINTOS (camas vs. médicos)
camas <- 500; medicos <- 83
razon_cama_medico <- camas / medicos
razon_cama_medico

# (b) Proporción: el numerador es UN SUBCONJUNTO del denominador (los IAM están dentro de la población)
iam <- 1789; poblacion <- 32000
proporcion_pct   <- iam / poblacion * 100
proporcion_x1000 <- iam / poblacion * 1000
c(porcentaje = round(proporcion_pct, 2), por_1000_hab = round(proporcion_x1000, 2))
```

::: {.callout-note}
## Razón vs. proporción: la diferencia que importa
En una **razón**, numerador y denominador son conjuntos distintos que no se solapan (camas y médicos son cosas diferentes). En una **proporción**, el numerador es un subconjunto del denominador (los 1,789 casos de IAM están *incluidos* en los 32,000 habitantes). Esta distinción determina, entre otras cosas, si el cociente puede superar 1 (una razón sí puede; una proporción, por definición, no).
:::

```{r}
mu <- n * p; sigma <- sqrt(n * p * (1 - p))
c(np = n*p, n1p = n*(1-p))   # ambos >= 5: aplica la aproximación

exacto <- 1 - pbinom(50, n, p)
aprox  <- 1 - pnorm(50.5, mu, sigma)

c(exacto = exacto, aproximado = aprox)
```

::: {.callout-note}
## Lo que deberías notar
La diferencia entre exacto (0.0436) y aproximado (0.0401) es un poco mayor aquí que en el Ítem 61 — la aproximación normal tiende a perder algo de precisión en las colas (valores alejados de la media) comparada con el centro de la distribución. Aun así, para fines prácticos (decidir si el proceso está fuera de control, por ejemplo), ambos valores llevan a la misma conclusión.
:::

## Bloque 25 · Función generadora de momentos

### Ítem 63 — Momentos de una Bernoulli, paso a paso

**Enunciado:** a partir de la FGM de una Bernoulli($p$), $M(t)=1-p+pe^t$, calcule $E[X]$ y $\text{Var}(X)$ derivando y evaluando en $t=0$ — primero a mano, luego verificando en R con derivación numérica.

```{r}
p <- 0.35   # un valor concreto para verificar numéricamente

M <- function(t) 1 - p + p * exp(t)

h <- 1e-6
E_X   <- (M(h) - M(-h)) / (2*h)
E_X2  <- (M(h) - 2*M(0) + M(-h)) / h^2
Var_X <- E_X2 - E_X^2

c(E_X = E_X, Var_X = Var_X, p_teorico = p, "p(1-p)_teorico" = p*(1-p))
```

::: {.callout-important}
## El álgebra detrás del chunk
A mano: $M'(t)=pe^t$, así que $M'(0)=p=E[X]$. $M''(t)=pe^t$ también, así que $M''(0)=p=E[X^2]$. Entonces $\text{Var}(X)=E[X^2]-E[X]^2=p-p^2=p(1-p)$ — coincide exactamente con lo que ya sabías de la tabla del Tema P6d, y con el resultado numérico de arriba.
:::

### Ítem 64 — Identificar una suma usando FGM

**Enunciado:** $X\sim\text{Poisson}(3)$ y $Y\sim\text{Poisson}(5)$, independientes. (a) Use el producto de sus FGM para identificar la distribución de $X+Y$. (b) Calcule $P(X+Y=10)$.

```{r}
lambda_X <- 3; lambda_Y <- 5

# (a) Verificación algebraica: el producto de las FGM tiene forma de Poisson(lambda_X + lambda_Y)
M_pois <- function(t, lambda) exp(lambda * (exp(t) - 1))
t_prueba <- seq(-1, 1, 0.2)
max(abs(M_pois(t_prueba, lambda_X) * M_pois(t_prueba, lambda_Y) - M_pois(t_prueba, lambda_X + lambda_Y)))

# (b) Con X+Y ~ Poisson(8):
p_suma_10 <- dpois(10, lambda_X + lambda_Y)
p_suma_10
```

::: {.ficha-resultado}
La diferencia máxima entre el producto de FGM y la FGM de Poisson(8) es esencialmente cero: confirma que $X+Y\sim\text{Poisson}(8)$. Con eso, $P(X+Y=10)=0.0993$ — un cálculo directo con `dpois()`, sin necesidad de convolucionar las dos distribuciones originales.
:::
