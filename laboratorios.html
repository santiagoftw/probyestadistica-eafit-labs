Bloque 0 · Cómo importar los datos

Importar bien el archivo es el primer obstáculo real de cualquier laboratorio. Estas son las cuatro opciones, de la más recomendada a la más manual:

  • Opción A · Ruta relativa (proyecto)
  • Opción B · Posit Cloud
  • Opción C · Fijar el directorio con setwd()
  • Opción D · Selección interactiva

Si trabajas dentro de un proyecto de RStudio (o clonaste el repositorio del curso), y el CSV está en una subcarpeta data/, basta con la ruta relativa:

datos <- read.csv("data/BaseLaboratorio1.csv")

Es la opción más portable: funciona igual en cualquier computador que tenga la misma estructura de carpetas. Requisito: el directorio de trabajo debe ser la raíz del proyecto (verifícalo con getwd()).

En Posit Cloud, los archivos que subes quedan en /cloud/project/. Sube el CSV con el botón “Upload” del panel Files, y luego:

datos <- read.csv("/cloud/project/BaseLaboratorio1.csv")

Esta es exactamente la ruta que usa la solución oficial del laboratorio del curso.

Puedes indicarle a R en qué carpeta buscar los archivos con setwd(), y después leer con el nombre del archivo solamente:

setwd("C:/Users/tu_usuario/Documents/estadistica")  # Windows
# setwd("/Users/tu_usuario/Documents/estadistica")  # Mac
datos <- read.csv("BaseLaboratorio1.csv")

Advertencia: la ruta depende de cómo esté organizado tu computador — un script con setwd() de rutas absolutas no funcionará en el computador de tu compañero. Úsalo para trabajo personal, no para scripts que vayas a compartir.

Si no quieres escribir ninguna ruta, file.choose() abre una ventana para navegar hasta el archivo:

datos <- read.csv(file.choose())

Cómodo para una sesión rápida, pero no reproducible: quien corra tu script tendrá que buscar el archivo a mano cada vez. Evítalo en trabajos entregables.

ImportantLos argumentos de read.csv() que debes conocer

read.csv() asume separador de columnas , y punto decimal .. Si tu archivo viene de un Excel en español (separador ; y decimal ,), esos supuestos fallan y debes declararlos explícitamente:

datos <- read.table("archivo.csv", header = TRUE, sep = ";", dec = ",")
  • header = TRUE: la primera fila trae los nombres de las columnas.
  • sep: el carácter que separa columnas ("," o ";").
  • dec: el carácter decimal ("." o ",").

De hecho, read.csv() es solo un atajo de read.table() con sep = "," y header = TRUE ya predefinidos. Si al importar ves una sola columna gigante con todo pegado, casi siempre el problema es el sep.

Verifica siempre la importación antes de analizar — estas dos líneas te ahorran horas de errores silenciosos:

El dataset tiene 7 variables. Dos son categóricas: Year y Country; el resto son cuantitativas continuas, asociadas a la producción anual de energía: SolarEnergy, WindEnergy, HydroEnergy, OtherRenewableEnergy, TotalRenewableEnergy. Ítem 13 — Probabilidad de un número par (teórica vs. simulada)

¿Qué tan cerca esperas que quede la frecuencia simulada de la probabilidad teórica con solo 1000 lanzamientos?

Code 
prob_par <- 3 / 6  # hay 3 números pares en un dado de 6 caras

set.seed(123)
lanzamientos <- sample(1:6, size = 1000, replace = TRUE)
frecuencia_par <- mean(lanzamientos %% 2 == 0)

prob_par
[1] 0.5
Code

La frecuencia simulada (0.497) está muy cerca del valor teórico (0.5) — es la Ley de los Grandes Números en acción: entre más lanzamientos, más se acerca la frecuencia relativa a la probabilidad teórica.

Ítem 15 — Diferencia simétrica de eventos

Enunciado: en una línea de producción, \(P(A)=0.3\) (defecto A), \(P(B)=0.4\) (defecto B), \(P(A\cap B)=0.1\). Calcule la probabilidad de que un producto tenga exactamente uno de los dos defectos (diferencia simétrica, \(A\Delta B\)) y la probabilidad de que tenga al menos uno.

Code 
p_A <- 0.3
p_B <- 0.4
p_A_int_B <- 0.1

# Diferencia simétrica: A∆B = (A∪B) - (A∩B)
p_diferencia_simetrica <- p_A + p_B - 2 * p_A_int_B
p_al_menos_uno <- p_A + p_B - p_A_int_B

list(diferencia_simetrica = p_diferencia_simetrica, al_menos_uno = p_al_menos_uno)
$diferencia_simetrica
[1] 0.5

$al_menos_uno
[1] 0.6
Tip💡 Truco de interpretación

\(A\Delta B\) resta la intersección dos veces (en vez de una, como en \(A\cup B\)) porque quiere excluir por completo los casos donde ocurren ambos eventos a la vez, no solo contarlos una vez. Compara la fórmula con la de \(P(A\cup B)\) del ítem anterior. Ver más trucos →

Esa reducción es el efecto de la diversificación — funciona precisamente porque los activos no están perfectamente correlacionados (\(\rho=0.5<1\)). Ver más trucos →

Ítem 39 — Estimación de una proporción y efecto del tamaño de muestra

Enunciado: estime la tasa de fallos de un componente electrónico (50 fallos observados en un lote) para distintos tamaños de muestra, y observe el efecto del tamaño de muestra sobre la precisión de la estimación.

Code 
set.seed(123)
n_fallos_total <- 50
tamanos <- c(50, 100, 200, 500)

simular_tasa <- function(n_componentes, n_sim = 1000) {
  replicate(n_sim, {
    n_fallos <- rbinom(1, size = n_componentes, prob = n_fallos_total / (n_componentes + n_fallos_total))
    n_fallos / n_componentes
  })
}

resultados <- lapply(tamanos, simular_tasa)

par(mfrow = c(2, 2), mar = c(4, 4, 2, 1))
for (i in seq_along(tamanos)) {
  hist(resultados[[i]], main = paste("n =", tamanos[i]), xlab = "Proporción de fallos",
       col = "#4B8BC2", breaks = 20, xlim = c(0, 0.6))
}
Code 
par(mfrow = c(1, 1))

Con \(n\) pequeño (50), la proporción estimada varía muchísimo entre repeticiones y suele sobreestimar la tasa real; con \(n=500\), las estimaciones se concentran de forma mucho más ajustada alrededor del valor verdadero. Ilustra por qué el tamaño de muestra es la palanca más directa para reducir el error de estimación.

Bloque 14 · Estimación por intervalos

Ítem 40 — Intervalo de confianza del 95% para una media

Enunciado: una muestra de 120 estudiantes reporta un tiempo promedio de trabajo independiente de 15 horas/semana, con desviación estándar 3 horas. Calcule el intervalo de confianza del 95% para la media poblacional.

Code 
media_muestral <- 15; sd_muestral <- 3; n <- 120
confianza <- 0.95

SE <- sd_muestral / sqrt(n)
valor_critico <- qnorm(1 - (1 - confianza) / 2)
margen_error <- valor_critico * SE

c(inferior = media_muestral - margen_error, superior = media_muestral + margen_error)
inferior superior

La estructura estimación ± (valor crítico × error estándar) es la misma para casi cualquier intervalo de confianza clásico — solo cambian el valor crítico (normal, t, etc.) y la fórmula del error estándar según qué parámetro se está estimando. Ver más trucos →

Ítem 41 — Intervalo de confianza del 95% para una proporción (Wilson)

Enunciado: de una muestra de 300 estudiantes, 60% tienen empleo de medio tiempo. Calcule el intervalo de confianza del 95% para la proporción poblacional, usando el método de Wilson.

Code 
proporcion <- 0.60
n <- 300

# prop.test() viene en el paquete `stats` (base R, no requiere instalar nada)
# y calcula el intervalo de Wilson cuando correct = FALSE
prop.test(n * proporcion, n, correct = FALSE)$conf.int
[1] 0.5436366 0.6538348
attr(,"conf.level")
[1] 0.95
ImportantNota de compatibilidad

La solución oficial del laboratorio usa Hmisc::binconf(..., method = "wilson"), pero Hmisc no viene instalado por defecto en R/RStudio — hay que instalarlo aparte (install.packages("Hmisc")), y en algunos entornos (como Posit Cloud gratuito) la instalación puede fallar o tardar mucho por sus dependencias. prop.test() calcula exactamente el mismo intervalo de Wilson (verificado: da el mismo resultado, 0.544 a 0.654) sin depender de ningún paquete externo — viene incluido en el paquete stats, que R carga automáticamente al iniciar. Si en algún momento necesitas Hmisc específicamente, instálalo con install.packages("Hmisc") antes de tu primer library(Hmisc).

Note¿Por qué Wilson y no la fórmula clásica?

El método clásico (\(\hat{p}\pm z\sqrt{\hat{p}(1-\hat{p})/n}\)) puede dar intervalos mal calibrados cuando \(\hat{p}\) está cerca de 0 o 1, o con \(n\) moderado. Wilson corrige ese problema y es el método que recomiendan la mayoría de paquetes estadísticos modernos como opción por defecto.

Bloque 15 · Pruebas de hipótesis

Ítem 42 — Prueba t: ¿son distintos dos algoritmos?

Enunciado: se comparan dos algoritmos de interacción midiendo su tiempo de respuesta (\(A\sim N(55,15^2)\), \(B\sim N(50,5^2)\), 1000 usuarios cada uno). Plantee el contraste de hipótesis y concluya.

  • Hipótesis
  • Código y conclusión

\(H_0: \mu_A = \mu_B\) vs. \(H_1: \mu_A \ne \mu_B\) (contraste bilateral). El estadístico de prueba sigue una distribución t de Student (Welch, porque no se asume igualdad de varianzas).

Code 
set.seed(42)
n_A <- 1000; n_B <- 1000
tiempos_A <- rnorm(n_A, mean = 55, sd = 15)
tiempos_B <- rnorm(n_B, mean = 50, sd = 5)

t.test(tiempos_A, tiempos_B)

    Welch Two Sample t-test

data:  tiempos_A and tiempos_B
t = 9.2702, df = 1211.3, p-value < 2.2e-16
alternative hypothesis: true difference in means is not equal to 0
95 percent confidence interval:
 3.657391 5.621056
sample estimates:
mean of x mean of y 
 54.61263  49.97341

Con un p-valor prácticamente cero (< 2.2e-16), se rechaza \(H_0\): hay evidencia estadística muy fuerte de que los tiempos de respuesta promedio de los dos algoritmos son distintos. El intervalo de confianza de la diferencia (aprox. 3.7 a 5.6) tampoco incluye el cero, lo cual es consistente con el rechazo.

::: {.callout-important}
## Los argumentos de `read.csv()` que debes conocer
`read.csv()` asume separador de columnas `,` y punto decimal `.`. Si tu archivo viene de un Excel en español (separador `;` y decimal `,`), esos supuestos fallan y debes declararlos explícitamente:

```r
datos <- read.table("archivo.csv", header = TRUE, sep = ";", dec = ",")
```

- `header = TRUE`: la primera fila trae los nombres de las columnas.
- `sep`: el carácter que separa columnas (`","` o `";"`).
- `dec`: el carácter decimal (`"."` o `","`).

De hecho, `read.csv()` es solo un atajo de `read.table()` con `sep = ","` y `header = TRUE` ya predefinidos. Si al importar ves una sola columna gigante con todo pegado, casi siempre el problema es el `sep`.
:::

**Verifica siempre la importación antes de analizar** — estas dos líneas te ahorran horas de errores silenciosos:

```{r}
datos <- read.csv("data/BaseLaboratorio1.csv")
```

### Ítem 17 — "Al menos uno": una fórmula mal aplicada (rigor)

**Enunciado:** dos eventos ocurren con $\pi_1=0.4$ y $\pi_2=0.5$, y $P(A\cap B)=0.2$. Calcule la probabilidad de que ocurra al menos uno de los dos y verifique por simulación.

::: {.ficha-prediccion}
Antes de mirar el código: ¿la expresión $1-(\pi_1+\pi_2-\pi_{12})$ calcula "al menos uno" o calcula otra cosa?
:::

```{r}

prob_al_menos_uno
```

::: {.callout-important}
## Corrección de rigor
La solución oficial del laboratorio calcula "al menos uno" como `1-(p1+p2-p12)` y obtiene 0.3 — pero esa expresión es en realidad $P(\text{ninguno de los dos})=1-P(A\cup B)$, no $P(\text{al menos uno})$. La simulación honesta del propio laboratorio lo delata: da 0.6945, muy lejos de 0.3 pero razonablemente cerca del valor correcto $P(A\cup B)=p_1+p_2-p_{12}=0.7$. Cuando el resultado simulado y el teórico no coinciden, el primer sospechoso es la fórmula, no la simulación — aquí, la clave es leer la fórmula de complemento con cuidado: $1-P(A\cup B)$ es el complemento de "al menos uno", es decir, "ninguno". Este es el mismo error que se documentó en el banco de ejercicios del Módulo 2 (ejercicio 1), donde se dejó explícitamente como ejercicio de detección de errores.
:::

### Ítem 29 — Monedas: conjunta, marginal y condicional (con corrección)

**Enunciado:** se lanzan 3 monedas balanceadas. $Y_1$ = número de caras. $Y_2$ = ganancia de una apuesta: \$1 si la primera cara sale en el tiro 1, \$2 si sale en el tiro 2, \$3 si sale en el tiro 3, y $-\$1$ si no sale ninguna cara. Encuentre la función de probabilidad conjunta, la marginal de $Y_2$, y $P(Y_1=3\,|\,Y_2=1)$.

::: {.ficha-prediccion}
$Y_2$ depende del *momento* de la primera cara, y $Y_1$ del *número total* de caras — dos aspectos distintos del mismo lanzamiento. ¿Esperas que sean independientes?
:::

```{r}
monedas <- expand.grid(t1 = c("C", "S"), t2 = c("C", "S"), t3 = c("C", "S"))
monedas$Y1 <- rowSums(monedas[, 1:3] == "C")
monedas$Y2 <- apply(monedas[, 1:3], 1, function(fila) {
  pos <- which(fila == "C")
  if (length(pos) == 0) return(-1)
  min(pos)
})

prob_matrix <- table(monedas$Y1, monedas$Y2) / nrow(monedas)
prob_matrix

marginal_Y2 <- colSums(prob_matrix)
marginal_Y2

p_Y1_3_dado_Y2_1 <- prob_matrix["3", "1"] / marginal_Y2["1"]
p_Y1_3_dado_Y2_1
```

::: {.callout-important}
## Corrección de rigor
La solución oficial de este laboratorio construye la tabla conjunta con una función que solo cubre la diagonal ($Y_1=y \Rightarrow Y_2=y$), lo que deja fuera combinaciones reales: por ejemplo, `CCS` y `CSC` dan ambas $Y_1=2$ pero con la primera cara en el tiro 1 ($Y_2=1$), no en el tiro 2. Esa función asigna probabilidad 0 a `(Y1=2, Y2=1)` cuando en realidad vale $2/8$, y de paso hace que la marginal de $Y_2$ salga uniforme (0.125 en cada valor) cuando la real es $P(Y_2{=}1){=}0.5$, $P(Y_2{=}2){=}0.25$, $P(Y_2{=}3){=}0.125$, $P(Y_2{=}{-1}){=}0.125$. La forma robusta de evitar este tipo de error — y la que se usa arriba — es **enumerar los 8 resultados del espacio muestral y contar**, en vez de escribir de memoria una fórmula cerrada para la probabilidad conjunta. Esta misma corrección ya se aplicó al Tema P8 del Módulo 2.
:::

::: {.ficha-resultado}
Con la tabla corregida, $P(Y_1{=}3\,|\,Y_2{=}1)=0.25$: saber que ganaste \$1 (la cara salió en el primer tiro) sí cambia la probabilidad de haber sacado 3 caras respecto a la marginal $P(Y_1{=}3)=0.125$ — confirma que **no son independientes**.
:::

### Ítem 30 — Ejecutivos: conjunta hipergeométrica y condicional (con corrección)

**Enunciado:** de 9 ejecutivos (4 casados, 3 solteros, 2 divorciados) se seleccionan 3 al azar. $Y_1$ = número de casados, $Y_2$ = número de solteros seleccionados. (1) Encuentre la conjunta. (2) La marginal de $Y_1$. (3) $P(Y_1{=}1\,|\,Y_2{=}2)$. (4) Si $Y_3=3-Y_1-Y_2$ es el número de divorciados, calcule $P(Y_3{=}1\,|\,Y_2{=}1)$.

```{r}
total <- 9; casados <- 4; solteros <- 3; divorciados <- 2; sel <- 3

prob_conjunta <- function(y1, y2) {
  y3 <- sel - y1 - y2
  if (y3 < 0 || y3 > divorciados) return(0)
  (choose(casados, y1) * choose(solteros, y2) * choose(divorciados, y3)) / choose(total, sel)
}

Y1 <- 0:3; Y2 <- 0:3
prob_matrix <- outer(Y1, Y2, Vectorize(prob_conjunta))
rownames(prob_matrix) <- paste0("Y1=", Y1); colnames(prob_matrix) <- paste0("Y2=", Y2)
round(prob_matrix, 4)

marginal_Y1 <- rowSums(prob_matrix)
marginal_Y1

# (3) P(Y1=1 | Y2=2)
p_Y1_1_dado_Y2_2 <- prob_conjunta(1, 2) / sum(prob_matrix[, "Y2=2"])
p_Y1_1_dado_Y2_2

# (4) P(Y3=1 | Y2=1): si Y2=1, Y3=1 exige Y1 = 3-1-1 = 1 (no Y1=2)
p_Y2_1 <- sum(prob_matrix[, "Y2=1"])
p_Y3_1_dado_Y2_1 <- prob_conjunta(1, 1) / p_Y2_1
p_Y3_1_dado_Y2_1
```

::: {.callout-important}
## Corrección de rigor
La solución oficial calcula el punto (4) así: `prob_Y1_2_Y2_1 <- prob_joint(2, 1)` dividido entre una variable `prob_Y2_1` que **no se redefine** en ese punto del documento — sigue guardando el valor 0.125 de un ejercicio anterior (el de las monedas), no la marginal de este problema. El resultado que imprime, 1.714286, ya es una señal de alerta por sí sola: **ninguna probabilidad puede ser mayor que 1**. Además, usa $Y_1{=}2$ cuando la condición $Y_3{=}1, Y_2{=}1$ en realidad exige $Y_1{=}3-1-1{=}1$. Al corregir ambos puntos (variable correcta y valor de $Y_1$ correcto), $P(Y_3{=}1\,|\,Y_2{=}1)\approx0.533$. La lección: reutilizar nombres de variable entre secciones de un mismo script es una fuente común de errores silenciosos — y un resultado fuera del rango válido (aquí, una "probabilidad" mayor a 1) siempre debe hacer sospechar del código antes que del modelo.
:::

## Bloque 9 · Covarianza y correlación de variables aleatorias

### Ítem 31 — Sistema de producción: demanda, tiempo y costo correlacionados

**Enunciado:** simule tres variables — demanda $D\sim N(1000, 200^2)$, tiempo $T\sim N(50,10^2)$, costo $C\sim N(5000,800^2)$ — con correlaciones $\text{cor}(D,T)=0.6$, $\text{cor}(D,C)=0.4$, $\text{cor}(T,C)=0.3$. Calcule la covarianza entre cada par y la matriz de correlación resultante.

```{r}
#| message: false
library(MASS)

mean_D <- 1000; sd_D <- 200
mean_T <- 50;   sd_T <- 10
mean_C <- 5000; sd_C <- 800
cor_DT <- 0.6; cor_DC <- 0.4; cor_TC <- 0.3

cov_matrix <- matrix(c(
  sd_D^2,             cor_DT * sd_D * sd_T, cor_DC * sd_D * sd_C,
  cor_DT * sd_D * sd_T, sd_T^2,             cor_TC * sd_T * sd_C,
  cor_DC * sd_D * sd_C, cor_TC * sd_T * sd_C, sd_C^2
), nrow = 3)

set.seed(123)
variables <- mvrnorm(10000, mu = c(mean_D, mean_T, mean_C), Sigma = cov_matrix)
colnames(variables) <- c("Demanda", "Tiempo", "Costo")

cov(variables)
cor(variables)
```

::: {.callout-note}
## Conecta con el Tema 8
Esta es exactamente la misma lógica de covarianza y correlación del Módulo 1 (mtcars: peso vs. consumo), pero ahora generando los datos correlacionados en vez de solo medirlos en datos ya existentes — `mvrnorm()` es la herramienta que permite *simular* con una estructura de correlación específica.
:::

### Ítem 32 — Propagación: vida útil como función de dos variables correlacionadas

**Enunciado:** resistencia $R\sim N(500,50^2)$ MPa y módulo de elasticidad $E\sim N(200,20^2)$ GPa, con $\text{cor}(R,E)=0.6$. La vida útil se modela como $L=R^2/E$. Simule 10,000 escenarios y calcule media y desviación estándar de $L$, y la correlación entre $L$ y $R$.

```{r}
mean_R <- 500; sd_R <- 50
mean_E <- 200; sd_E <- 20
cor_RE <- 0.6

cov_matrix <- matrix(c(sd_R^2, cor_RE * sd_R * sd_E,
                        cor_RE * sd_R * sd_E, sd_E^2), 2, 2)

set.seed(123)
propiedades <- mvrnorm(10000, mu = c(mean_R, mean_E), Sigma = cov_matrix)
R <- propiedades[, 1]; E <- propiedades[, 2]
vida_util <- R^2 / E

list(
  media_vida_util = mean(vida_util),
  sd_vida_util = sd(vida_util),
  correlacion_L_R = cor(vida_util, R)
)
```

::: {.callout-tip}
## 💡 Truco de interpretación
$L$ es una función **no lineal** de $R$ y $E$, así que no hay una fórmula cerrada simple para su media o varianza (a diferencia de una combinación lineal). Por eso se simula: generar miles de escenarios y calcular la media/varianza empíricas es, en la práctica, la manera más directa de propagar la incertidumbre a través de una función complicada. ## Bloque 10 · Funciones de variables aleatorias

### Ítem 33 — ¿Cuál componente falla primero?

**Enunciado:** dos componentes A y B tienen tiempos de falla exponenciales independientes, con tasas $\lambda_A=0.1$ y $\lambda_B=0.2$. Determine, por simulación, la probabilidad de que el sistema falle por A antes que por B.

::: {.ficha-prediccion}
Si B falla en promedio el doble de rápido que A (tasa el doble de grande), ¿esperas que P(A falla primero) sea mayor o menor a 0.5?
:::

```{r}
lambda_A <- 0.1
lambda_B <- 0.2

set.seed(123)
tiempos_A <- rexp(10000, rate = lambda_A)
tiempos_B <- rexp(10000, rate = lambda_B)

prob_A_antes_B <- mean(tiempos_A < tiempos_B)
prob_A_antes_B
```

::: {.ficha-resultado}
Para dos exponenciales independientes, existe una fórmula cerrada exacta: $P(A<B)=\dfrac{\lambda_A}{\lambda_A+\lambda_B}$. Aquí eso da $0.1/(0.1+0.2)=0.333$, prácticamente idéntico al valor simulado — una buena verificación cruzada entre teoría y simulación.
:::

```{r}
lambda_A / (lambda_A + lambda_B)  # verificación teórica
```

### Ítem 34 — Rentabilidad de un portafolio de inversión

**Enunciado:** un portafolio combina el activo A ($\mu=8\%$, $\sigma=12\%$) y el activo B ($\mu=6\%$, $\sigma=10\%$), correlacionados con $\rho=0.5$, en proporciones 60%/40%. Simule la rentabilidad del portafolio y calcule su media y desviación estándar.

```{r}
mean_A <- 0.08; sd_A <- 0.12
mean_B <- 0.06; sd_B <- 0.10
rho <- 0.5

cov_matrix <- matrix(c(sd_A^2, rho * sd_A * sd_B,
                        rho * sd_A * sd_B, sd_B^2), 2, 2)

set.seed(123)
normales <- mvrnorm(10000, mu = c(mean_A, mean_B), Sigma = cov_matrix)
rentabilidad_portafolio <- 0.6 * normales[, 1] + 0.4 * normales[, 2]

c(media = mean(rentabilidad_portafolio), sd = sd(rentabilidad_portafolio))
```

::: {.callout-tip}
## 💡 Truco de interpretación
Compara la desviación estándar del portafolio (~9.8%) con el promedio ponderado de las desviaciones individuales ($0.6\times12\%+0.4\times10\%=11.2\%$): el portafolio combinado es **menos volátil** que ese promedio simple. Esa reducción es el efecto de la diversificación — funciona precisamente porque los activos no están perfectamente correlacionados ($\rho=0.5<1$). [Ver más trucos →](../recursos.qmd)
:::

### Ítem 35 — Distribución muestral de la media según el tamaño de muestra

**Enunciado:** simule la distribución muestral de la media de una $N(100, 15^2)$ para tamaños de muestra $n=10,30,50$ y compare.

```{r}
set.seed(123)
mean_pob <- 100; sd_pob <- 15
tamanos <- c(10, 30, 50)

simular_medias <- function(n, n_sim = 1000) {
  replicate(n_sim, mean(rnorm(n, mean = mean_pob, sd = sd_pob)))
}

resultados <- lapply(tamanos, simular_medias)

par(mfrow = c(1, 3))
for (i in seq_along(tamanos)) {
  hist(resultados[[i]], main = paste("n =", tamanos[i]), xlab = "Media muestral",
       col = "#4B8BC2", breaks = 20, xlim = c(80, 120))
}
par(mfrow = c(1, 1))
```

::: {.ficha-resultado}
Las tres distribuciones están centradas en 100 (la media poblacional no cambia), pero se **angostan** a medida que $n$ crece: con $n=50$ la media muestral varía mucho menos entre repeticiones que con $n=10$. Esto es consecuencia directa de que $\text{sd}(\bar{X}) = \sigma/\sqrt{n}$.

## Bloque 12 · Teorema Central del Límite

### Ítem 37 — TCL con tiempos de interacción no observados como normales

**Enunciado:** el tiempo de interacción de usuarios con un prototipo tiene $\mu=30$, $\sigma=10$ segundos. Tome muestras de tamaño 50 y muestre que la distribución de las medias muestrales se aproxima a una normal, aunque los datos individuales no lo sean.

```{r}
set.seed(123)
media_interaccion <- 30; sd_interaccion <- 10
n_muestra <- 50

medias_muestrales <- replicate(1000, mean(rnorm(n_muestra, media_interaccion, sd_interaccion)))
sd_teorica <- sd_interaccion / sqrt(n_muestra)

hist(medias_muestrales, breaks = 25, col = "#4B8BC2", probability = TRUE,
     main = "TCL: distribución de medias muestrales (n = 50)",
     xlab = "Media muestral")
curve(dnorm(x, mean = media_interaccion, sd = sd_teorica), add = TRUE, col = "#FFB903", lwd = 2)
abline(v = media_interaccion, col = "#004B85", lty = 2, lwd = 2)
```

::: {.callout-important}
## Por qué importa el TCL
El Teorema Central del Límite es la razón por la que casi todos los intervalos de confianza y pruebas de hipótesis "clásicas" (las que vienen en el Bloque 14 y 15) pueden usar la distribución normal como referencia, **sin importar la forma de la distribución original de los datos individuales** — siempre que el tamaño de muestra sea razonablemente grande.
:::

### Ítem 39 — Estimación de una proporción y efecto del tamaño de muestra

**Enunciado:** estime la tasa de fallos de un componente electrónico (50 fallos observados en un lote) para distintos tamaños de muestra, y observe el efecto del tamaño de muestra sobre la precisión de la estimación.

```{r}
set.seed(123)
n_fallos_total <- 50
tamanos <- c(50, 100, 200, 500)

simular_tasa <- function(n_componentes, n_sim = 1000) {
  replicate(n_sim, {
    n_fallos <- rbinom(1, size = n_componentes, prob = n_fallos_total / (n_componentes + n_fallos_total))
    n_fallos / n_componentes
  })
}

resultados <- lapply(tamanos, simular_tasa)

par(mfrow = c(2, 2), mar = c(4, 4, 2, 1))
for (i in seq_along(tamanos)) {
  hist(resultados[[i]], main = paste("n =", tamanos[i]), xlab = "Proporción de fallos",
       col = "#4B8BC2", breaks = 20, xlim = c(0, 0.6))
}
par(mfrow = c(1, 1))
```

::: {.ficha-resultado}
Con $n$ pequeño (50), la proporción estimada varía muchísimo entre repeticiones y suele sobreestimar la tasa real; con $n=500$, las estimaciones se concentran de forma mucho más ajustada alrededor del valor verdadero. Ilustra por qué el tamaño de muestra es la palanca más directa para reducir el error de estimación.
:::

## Bloque 14 · Estimación por intervalos

### Ítem 40 — Intervalo de confianza del 95% para una media

**Enunciado:** una muestra de 120 estudiantes reporta un tiempo promedio de trabajo independiente de 15 horas/semana, con desviación estándar 3 horas. Calcule el intervalo de confianza del 95% para la media poblacional.

```{r}
media_muestral <- 15; sd_muestral <- 3; n <- 120
confianza <- 0.95

SE <- sd_muestral / sqrt(n)
valor_critico <- qnorm(1 - (1 - confianza) / 2)
margen_error <- valor_critico * SE

c(inferior = media_muestral - margen_error, superior = media_muestral + margen_error)
```

::: {.callout-tip}
## 💡 Truco de interpretación
La estructura **estimación ± (valor crítico × error estándar)** es la misma para casi cualquier intervalo de confianza clásico — solo cambian el valor crítico (normal, t, etc.) y la fórmula del error estándar según qué parámetro se está estimando. [Ver más trucos →](../recursos.qmd)
:::

### Ítem 41 — Intervalo de confianza del 95% para una proporción (Wilson)

**Enunciado:** de una muestra de 300 estudiantes, 60% tienen empleo de medio tiempo. Calcule el intervalo de confianza del 95% para la proporción poblacional, usando el método de Wilson.

```{r}
proporcion <- 0.60
n <- 300

# prop.test() viene en el paquete `stats` (base R, no requiere instalar nada)
# y calcula el intervalo de Wilson cuando correct = FALSE
prop.test(n * proporcion, n, correct = FALSE)$conf.int
```

::: {.callout-important}
## Nota de compatibilidad
La solución oficial del laboratorio usa `Hmisc::binconf(..., method = "wilson")`, pero `Hmisc` **no viene instalado por defecto** en R/RStudio — hay que instalarlo aparte (`install.packages("Hmisc")`), y en algunos entornos (como Posit Cloud gratuito) la instalación puede fallar o tardar mucho por sus dependencias. `prop.test()` calcula exactamente el mismo intervalo de Wilson (verificado: da el mismo resultado, 0.544 a 0.654) sin depender de ningún paquete externo — viene incluido en el paquete `stats`, que R carga automáticamente al iniciar. Si en algún momento necesitas `Hmisc` específicamente, instálalo con `install.packages("Hmisc")` antes de tu primer `library(Hmisc)`.
:::

::: {.callout-note}
## ¿Por qué Wilson y no la fórmula clásica?
El método clásico ($\hat{p}\pm z\sqrt{\hat{p}(1-\hat{p})/n}$) puede dar intervalos mal calibrados cuando $\hat{p}$ está cerca de 0 o 1, o con $n$ moderado. Wilson corrige ese problema y es el método que recomiendan la mayoría de paquetes estadísticos modernos como opción por defecto.
:::

## Bloque 15 · Pruebas de hipótesis

### Ítem 42 — Prueba t: ¿son distintos dos algoritmos?

**Enunciado:** se comparan dos algoritmos de interacción midiendo su tiempo de respuesta ($A\sim N(55,15^2)$, $B\sim N(50,5^2)$, 1000 usuarios cada uno). Plantee el contraste de hipótesis y concluya.

::: {.panel-tabset}

## Hipótesis
$H_0: \mu_A = \mu_B$ vs. $H_1: \mu_A \ne \mu_B$ (contraste bilateral). El estadístico de prueba sigue una distribución t de Student (Welch, porque no se asume igualdad de varianzas).

## Código y conclusión

```{r}
set.seed(42)
n_A <- 1000; n_B <- 1000
tiempos_A <- rnorm(n_A, mean = 55, sd = 15)
tiempos_B <- rnorm(n_B, mean = 50, sd = 5)

t.test(tiempos_A, tiempos_B)
```

Con un p-valor prácticamente cero (< 2.2e-16), se **rechaza $H_0$**: hay evidencia estadística muy fuerte de que los tiempos de respuesta promedio de los dos algoritmos son distintos. El intervalo de confianza de la diferencia (aprox. 3.7 a 5.6) tampoco incluye el cero, lo cual es consistente con el rechazo.

:::

### Ítem 43 — Comparando varianzas y medias: instrumento nuevo vs. estándar

**Enunciado:** se comparan mediciones de un instrumento nuevo ($\mu=0.07$, $\sigma=0.05$) contra uno estándar ($\mu=0.08$, $\sigma=0.010$), 100 mediciones cada uno. Evalúe si difieren en varianza y en media.

```{r}
set.seed(42)
n <- 100
nuevo <- rnorm(n, mean = 0.07, sd = 0.05)
estandar <- rnorm(n, mean = 0.08, sd = 0.010)

var.test(nuevo, estandar)
t.test(nuevo, estandar)
```

::: {.ficha-resultado}
La prueba F de varianzas da un p-valor prácticamente cero: el instrumento nuevo es **significativamente más disperso** (menos preciso) que el estándar — su desviación estándar real (0.05) es 5 veces mayor. Sin embargo, la prueba t sobre las medias da p ≈ 0.16: **no hay evidencia suficiente para decir que difieran en promedio**. Es un buen ejemplo de que "distinto en precisión" y "distinto en promedio" son preguntas independientes — un instrumento puede ser igual de "centrado" pero mucho más ruidoso.
:::

::: {.callout-tip}
## 💡 Truco de interpretación
No confundas "no rechazar $H_0$" con "demostrar que $H_0$ es cierta". Un p-valor de 0.16 en la prueba t solo dice que los datos no dan evidencia suficiente para descartar medias iguales — no prueba que las medias sean exactamente iguales. [Ver más trucos →](../recursos.qmd)
:::
