🪙 Antes de tocar una fórmula…

Vas a lanzar una moneda 100 veces. Antes de correr nada: ¿cuántas caras crees que saldrán? ¿Estás seguro de ese número? Si lo repites, ¿esperas exactamente lo mismo?

Escribe tu predicción antes de seguir leyendo: ¿cuántas caras esperas en 100 lanzamientos, y qué tan seguro estás (mucho / algo / poco)?

🔬 Exploremos

Este código simula 100 lanzamientos de una moneda (1 = cara, 0 = sello). Ejecútalo en tu sesión de Posit Cloud y anota el resultado.

Code 
set.seed(2026)  # fijamos la semilla para que este resultado sea reproducible en el sitio
lanzamientos <- sample(c(0, 1), size = 100, replace = TRUE)
sum(lanzamientos)      # número de caras
[1] 47
Code 
mean(lanzamientos)     # proporción de caras
[1] 0.47
TipImportante sobre la semilla

El resultado de arriba siempre va a ser el mismo cada vez que se renderiza el sitio, porque fijamos set.seed(2026). En tu propia sesión de R, quita esa línea (o cambia el número) para ver que el resultado sí cambia entre corridas — esa es la aleatoriedad real que estamos explorando.

Corre el código dos veces seguidas sin cambiar nada. ¿Obtuviste el mismo número de caras ambas veces?

TipPregunta guía

¿Por qué el mismo código, corrido dos veces, te da resultados distintos? Discútelo con un compañero antes de seguir.

🎛️ Simulación: ¿qué pasa si cambias cuántas veces lanzas?

Mueve el control de la animación (▶ / la barra inferior) para ver cómo la proporción de caras se comporta según cuántos lanzamientos llevas acumulados.

Code 
library(plotly)
library(purrr)

set.seed(123)
n_max <- 2000
lanzamientos <- sample(c(0, 1), n_max, replace = TRUE)
cortes <- c(10, 50, 100, 250, 500, 1000, 2000)

df <- map_dfr(cortes, function(n) {
  data.frame(
    n = n,
    lanzamiento = 1:n,
    proporcion_cara = cumsum(lanzamientos[1:n]) / (1:n)
  )
})

plot_ly(df, x = ~lanzamiento, y = ~proporcion_cara, frame = ~n,
        type = "scatter", mode = "lines",
        line = list(color = "#004B85", width = 2)) |>
  layout(
    yaxis = list(range = c(0, 1), title = "Proporción de caras"),
    xaxis = list(title = "Número de lanzamiento"),
    shapes = list(list(
      type = "line", x0 = 0, x1 = 1, xref = "paper",
      y0 = 0.5, y1 = 0.5,
      line = list(dash = "dot", color = "#B37D00")
    ))
  ) |>
  animation_slider(currentvalue = list(prefix = "lanzamientos acumulados hasta n = "))
NoteLo que deberías notar

Con pocos lanzamientos la línea salta mucho. A medida que crece n, se acerca y se queda cerca de la línea punteada roja (50%), aunque casi nunca la toca exactamente.

💡 Discusión

  • ¿Coincidió tu predicción inicial con lo que observaste?
  • ¿Por qué la línea “salta” más al principio que al final?
  • ¿Qué le dirías a alguien que insiste en que 100 lanzamientos deben dar exactamente 50 caras?

📖 Ahora sí, la teoría

  • Consola vs. script
  • Vector
  • Función
  • Aleatoriedad

La consola es para probar algo rápido y que se pierde después. El script guarda tu trabajo para poder reproducirlo. Todo lo que hiciste arriba deberías guardarlo en un script, no solo en la consola.

Un vector es la estructura básica de R para guardar una colección de valores — exactamente lo que es lanzamientos: 100 (o 2000) resultados de 0 y 1 guardados en un solo objeto.

Una función es una “caja” que recibe un vector y devuelve una respuesta: sum() cuenta, mean() promedia, length() cuenta cuántos elementos hay. Ya usaste las tres sin saber que se llamaban así.

Cada vez que R “lanza la moneda” con sample(), genera un resultado distinto porque usa un generador de números aleatorios. Eso es exactamente lo que viste al correr el código dos veces.

Tip💡 Truco de interpretación

Si alguien te muestra “el resultado” de un solo experimento aleatorio (una encuesta pequeña, una sola corrida de un simulacro), pregúntate: ¿este resultado se parecería a otra corrida del mismo experimento? Con n pequeño, la respuesta suele ser “no mucho” — desconfía de conclusiones fuertes basadas en pocas repeticiones. Ver más trucos →

Otro ejemplo: definir tu propia función (precio por pie cuadrado)

No todo tiene que venir de una función que ya existe en R — tú también puedes definir las tuyas. El precio por pie cuadrado es la fórmula perfecta para practicarlo, porque la vamos a poder aplicar directamente sobre las columnas que ya cargaste:

Code 
precio_por_pie2 <- function(precio, sqft) {
  precio / sqft
}

# Prueba con una casa de $150,000 y 2,000 pies cuadrados
precio_por_pie2(precio = 150000, sqft = 2000)
[1] 75

Y la misma función, aplicada a la vez sobre las 128 casas (aprovechando que R vectoriza las operaciones aritméticas):

Code 
houses$precio_pie2 <- precio_por_pie2(houses$Price, houses$SqFt)
mean(houses$precio_pie2)
[1] 65.12688
Code 
range(houses$precio_pie2)
[1] 42.01005 92.15686

Con los datos ya en un data frame, la indexación [fila, columna] te permite consultar un dato puntual sin filtrar por nombre — por ejemplo, el área en pies cuadrados (columna 3) de la casa en la fila 5:

Code 
houses[5, 3]   # fila 5, columna 3 (SqFt)
[1] 2130
Tip💡 Truco de interpretación

houses[5, 3] funciona, pero es frágil: si alguien reordena las columnas, deja de apuntar a SqFt. houses[5, "SqFt"] o houses$SqFt[5] dan el mismo resultado y no se rompen si cambia el orden de las columnas — prefiérelos en código que vayas a reutilizar. Ver más trucos →
